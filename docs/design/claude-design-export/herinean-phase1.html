One column, one accent, hairlines. Everything below is reproducible in hand-written CSS with no JavaScript: the whole system is eleven custom properties, two typefaces, a 1.25 type scale and a 0.5rem spacing scale.

Mono

One 1px hairline in --rule. No cards, shadows, gradients, icons, pills, avatars or animation.

Three notes for the build. The accent appears only on links and focus rings; the single exception is the failing colophon row, where the brief asks for a failure style and no second colour exists. The artboards below scale by container query units (cqw) so both widths can sit side by side on one sheet; production swaps them for vw in the same three clamps (gutter, title, portrait). Light and dark are selected here by a data-scheme attribute for comparison only; production ships :root plus one prefers-color-scheme: dark override and no toggle.

Which AI projects are worth funding in 2027

27 Sep 2026·Updated 3 Oct 2026·9 min read·Analysis

A board can approve an AI budget in twenty minutes and then spend two years finding out whether the project was fundable. The demo is never the problem. The demo is the reason the question gets asked badly.

I run engineering for a company that puts AI into retail and agricultural operations, so I see both ends: the pitch, and the third quarter after the pitch. What separates the projects that reach production from the ones that stay demos is not model quality. It is three unglamorous properties, and all three are visible before any money moves.

Three questions

Ask them in order. A project that fails the first one cannot be rescued by the other two.

1. Who owns the decision?

Every AI project changes a decision somebody is already accountable for — what to restock, which claim to review first, which field to spray. If the owner of that decision is not in the room when the project is scoped, the model will be built to produce an output nobody is permitted to act on.

A model nobody is accountable for acting on is a reporting tool with a research budget.

2. What does the model replace?

There are only three honest answers, and they price very differently.

  • A judgement made today by an expert, under time pressure, on incomplete data. Fundable.
  • A judgement made today by nobody, because there is no time to make it at all. Fundable, and usually cheaper than it looks.
  • A process that exists only in a slide. Not fundable yet — fund the process first.

3. What happens on a bad day?

Ask for the failure mode in plain words. “The model ranks the wrong three stores first and a regional manager loses a week” is an answer you can budget against. If nobody can describe the bad day, the project has not been thought about operationally, and the pilot will end in a disagreement about whether it worked.

What it looks like in a portfolio

Project Stage Cost / decision Decision owner
Restock priorityProduction€0.004Regional ops
Invoice triageProduction€0.011Finance lead
Yield forecastPilot€0.38Agronomy
Support assistantPaused—None

The column that predicts the outcome is the last one, not the third.

Instrument the decision, not the model

Whatever gets funded, tie the release gate to the decision it changes. A scorecard the project has to pass on every deploy keeps the monthly review concrete:

decision: restock_priority
owner:    ops.regional_manager
baseline: manual_ranking_2025_q3
gate:
  precision_at_10: ">= 0.72"
  latency_p95_ms:  "< 900"
  override_rate:   "< 0.25"   # disagreement is signal

Three numbers, reviewed monthly, in language the decision owner can argue with.1

Notes

  1. The override rate matters most. Above a quarter, the model is being ignored, whatever the accuracy says. ↩

Ce ar trebui să întrebe un board despre AI înainte de a aproba bugetul

27 sept. 2026·9 min de citit·AI și guvernanță

Un consiliu de administrație poate aproba un buget de AI în douăzeci de minute și apoi poate afla, în următorii doi ani, dacă proiectul merita finanțat. Demonstrația nu este niciodată problema. Demonstrația este motivul pentru care întrebarea este pusă prost.

Conduc partea de inginerie într-o companie care duce AI în operațiuni de retail și agricultură, așa că văd ambele capete: prezentarea și al treilea trimestru de după prezentare. Ceea ce separă proiectele care ajung în producție de cele care rămân demonstrații nu este calitatea modelului. Sunt trei proprietăți nespectaculoase, iar toate trei se văd înainte să se miște vreun ban.

Cinci întrebări, în ordine

Le pun în aceeași ordine de fiecare dată. Un proiect care cade la prima nu poate fi salvat de celelalte.

1. Cine deține decizia?

Orice proiect de AI schimbă o decizie de care răspunde deja cineva: ce se reaprovizionează, care dosar se verifică primul, care parcelă se tratează. Dacă proprietarul acelei decizii nu este în încăpere când se definește proiectul, modelul va produce un rezultat pe care nimeni nu are dreptul să îl folosească.

„Un model pentru care nimeni nu răspunde este un instrument de raportare cu buget de cercetare.”

2. Ce înlocuiește modelul?

Există doar trei răspunsuri oneste, iar ele se evaluează foarte diferit:

  • O judecată făcută astăzi de un expert, sub presiunea timpului, pe date incomplete. Se finanțează.
  • O judecată pe care astăzi nu o face nimeni, pentru că nu există timp. Se finanțează, și costă mai puțin decât pare.
  • Un proces care există doar într-un slide. Încă nu se finanțează — se finanțează procesul întâi.

3. Cum arată o zi proastă?

Cer descrierea modului de eșec în cuvinte simple. „Modelul pune primele trei magazine greșite în capul listei și un manager regional pierde o săptămână” este un răspuns pentru care se poate face buget. Dacă nimeni nu poate descrie ziua proastă, proiectul nu a fost gândit operațional.

Cum arată într-un portofoliu

Proiect Etapă Cost / decizie Deține decizia
Prioritate reaprovizionareProducție0,004 €Operațiuni
Triaj facturiProducție0,011 €Financiar
Prognoză recoltăPilot0,38 €Agronomie
Asistent de suportSuspendat—Nimeni

Coloana care prezice rezultatul este ultima, nu a treia.

Măsurați decizia, nu modelul

Orice se finanțează, legați condiția de lansare de decizia pe care o schimbă. O fișă de verificare pe care proiectul trebuie să o treacă la fiecare livrare menține discuția concretă:

decizie: prioritate_reaprovizionare
owner:   ops.manager_regional
referinta: clasare_manuala_2025_t3
prag:
  precizie_top_10: ">= 0,72"
  latenta_p95_ms:  "< 900"
  rata_suprascriere: "< 0,25"   # dezacordul e semnal

Trei numere, revizuite lunar, în limbajul în care proprietarul deciziei poate să le conteste.1

Note

  1. Rata de suprascriere contează cel mai mult. Peste un sfert, modelul este ignorat, oricât de bună ar fi acuratețea. ↩

Which AI projects are worth funding in 2027

27 Sep 2026·Updated 3 Oct 2026·9 min read·Analysis

A board can approve an AI budget in twenty minutes and then spend two years finding out whether the project was fundable. The demo is never the problem. The demo is the reason the question gets asked badly.

I run engineering for a company that puts AI into retail and agricultural operations, so I see both ends: the pitch, and the third quarter after the pitch. What separates the projects that reach production from the ones that stay demos is not model quality. It is three unglamorous properties, and all three are visible before any money moves.

Three questions

Ask them in order. A project that fails the first one cannot be rescued by the other two.

1. Who owns the decision?

Every AI project changes a decision somebody is already accountable for — what to restock, which claim to review first, which field to spray. If the owner of that decision is not in the room when the project is scoped, the model will be built to produce an output nobody is permitted to act on.

A model nobody is accountable for acting on is a reporting tool with a research budget.

2. What does the model replace?

There are only three honest answers, and they price very differently.

  • A judgement made today by an expert, under time pressure, on incomplete data. Fundable.
  • A judgement made today by nobody, because there is no time to make it at all. Fundable, and usually cheaper than it looks.
  • A process that exists only in a slide. Not fundable yet — fund the process first.

3. What happens on a bad day?

Ask for the failure mode in plain words. “The model ranks the wrong three stores first and a regional manager loses a week” is an answer you can budget against. If nobody can describe the bad day, the project has not been thought about operationally, and the pilot will end in a disagreement about whether it worked.

The column that predicts the outcome is the last one, not the third.

Instrument the decision, not the model

Whatever gets funded, tie the release gate to the decision it changes. A scorecard the project has to pass on every deploy keeps the monthly review concrete:

decision: restock_priority
owner:    ops.regional_manager
baseline: manual_ranking_2025_q3
gate:
  precision_at_10: ">= 0.72"
  latency_p95_ms:  "< 900"
  override_rate:   "< 0.25"   # disagreement is signal

Three numbers, reviewed monthly, in language the decision owner can argue with.1

Notes

  1. The override rate matters most. Above a quarter, the model is being ignored, whatever the accuracy says. ↩
